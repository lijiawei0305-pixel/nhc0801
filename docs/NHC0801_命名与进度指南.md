## 1. 名字拆解（按词条）

### 1.1 `g001` 两种含义（小心）

| 写法 | 含义 |
| --- | --- |
| **`runs/nhc0801-g001/`** | **generation** 总文件夹（里面放 g001/g002/g003… 所有组） |
| **分子组 g001** | 正线 pilot 那 5 个分子；teacher 在 `teacher_gpu_g001/` |

以后若另开一代训练目录，可能是 `runs/nhc0801-g002/`——那是 **generation 名**，与 **分子组 g002** 不是一回事。日常说「g002」默认指 **分子组 g002**。

### 1.2 `Epoch-0` / `e0` / `epoch0`

**同一件事的三种写法**：

| 写法 | 场合 |
| --- | --- |
| **Epoch-0** | 论文/ mindmap 正式名（「第 0 个 epoch」= **微调前** 官方权重） |
| **e0** | 口头 / 日志缩写 |
| **`epoch0/`** | 磁盘目录名 |

**它在算什么（科学）**：

```text
冻结几何 (gold XYZ)
  → 官方 AIMNet2（_0 权重，未微调）做 GAU_LOOSE 预优化
  → 交接 (handoff) 到 Parent
  → Parent-Level P01（ωB97M-D3BJ / def2-TZVPP）完整优化 + 单点
  → 脱质子标签
  → 与「纯 PySCF 参考」对比
```

**它不是**：

- 不是训练循环里的「第 0 轮梯度更新」日志；
- 不是 Final Test；
- **不是** 给 Train 分子刷基线（Train e0 = 无用功，合同禁止）。

### 1.3 `Val` / `Train` / `Val-only`

| 词 | 人话 |
| --- | --- |
| **molecular root / InChIKey** | 一个分子家族的身份证（如 `KZYKDQNIIMATMJ-UHFFFAOYSA-N`） |
| **endpoint** | 每个 root 有两端：`cation`（阳离子）+ `neutral`（中性）→ 常说 **1 root = 2 endpoints** |
| **Train** | 允许进入 **微调标签** 的分子（g001 正线固定 **3** 个 root） |
| **Val / Validation** | 只用于 **评估 / 选模 / e0 基线**，**禁止训练**（g001 正线固定 **2** 个 root） |
| **Val-only** | 本任务 **分子集合 = 仅 Val**，代码会 **拒绝 Train root** |

**g001 pilot 冻结名单**（正线）：

| 角色 | 数量 | InChIKey（缩写） |
| --- | ---: | --- |
| Train | 3 | `ACGCNT…` · `PDIYCC…` · `VNYHGZ…` |
| Val | 2 | `KZYKDQ…` · `RMEQTB…` |
| Final Test | 2 | **密封**，默认不算 |

→ pilot teacher 波 = 5 roots × 2 = **10 endpoints**。  
→ g001 e0 = 2 Val × 2 = **4 endpoints**（不是 10）。

### 1.4 标准名：`g00N Epoch-0`（不要叫「扩展 Val e0」）

每一批分子（g001 pilot、g002、g003…）都有自己的 **Epoch-0**，名字跟批号对齐：

| 标准名 | 分子（仅该批 Val） | 写哪里 | 谁在跑 |
| --- | --- | --- | --- |
| **g001 Epoch-0** | g001 两个 Val | `epoch0_val_batches/g001/` | `live_orchestrate --skip-train-live` |
| **g002 Epoch-0** | g002 两个 Val | `epoch0_val_batches/g002/` | `e0_val_queue_daemon` 派发 |
| **g003 Epoch-0** | g003 两个 Val | `epoch0_val_batches/g003/` | 同上 |
| **g00N Epoch-0** | g00N 的 `val_roots` | `epoch0_val_batches/g00N/` | 同上 |

| 废名 / 别再说 | 请改成 |
| --- | --- |
| 扩展 Val e0 | **g002 Epoch-0**（或对应批号） |
| 扩展批 e0 | **g00N Epoch-0** |
| 侧线 e0 | **g00N Epoch-0**（路径碰巧在 generation 目录下） |

**共同点**：都是 mindmap **步骤 3**；**都只算该批 Validation，不算该批 Train**；**磁盘模式完全一样** `epoch0_val_batches/<批号>/`。  
**路径说明**：各批 Epoch-0 都挂在 generation 目录 `runs/nhc0801-g001/` 下（GPU 批先囤在此 generation）——**任务名仍是 g00N Epoch-0**。  
**Val-only** 只是政策标签（禁止 Train），**不是**任务名称。

### 1.5 `teacher` / `wave` / `02c`

| 词 | 含义 |
| --- | --- |
| **teacher / g00N teacher** | 分子组 g00N 的老师轨迹（步骤 2）；目录 **`teacher_gpu_g00N/`** |
| **wave / 波** | 一次固定规模的并行战役（常写 **10 endpoints** = 一组） |
| **02c** | 某次资源 profile 标签（日志名如 `teacher_wave_02c.out`） |
| **切组队列**（程序：`gpu_autofill`） | 从刚性小分子池按序切出 **g003、g004…** 并做 teacher；**对外只报组号** |
| **3+2** | 每组 5 root：字典序前 3=Train、后 2=Val |

### 1.6 结果状态词

| 状态 | 人话 |
| --- | --- |
| **PASS / LIVE_*_PASS** | 该批/战役硬门槛通过 |
| **PARTIAL / LIVE_EPOCH0_PARTIAL** | 跑完了但有 root 失败（例如 handoff 挂了） |
| **FAIL / FAILED** | 失败（可查 receipt 里的 `catastrophic_reasons`） |
| **RUNNING** | 队列里正在算 |
| **PENDING** | 排队未开 |
| **EXTERNAL_DONE** | 本守护不重跑，由外部进程（如 live_orchestrate）负责 |

### 1.7 资源相关口头禅

| 说法 | 含义 |
| --- | --- |
| **gpu4pyscf** | GPU 版 PySCF 栈（teacher / 部分 parent） |
| **无 VASP 卡可跑 e0** | e0 的 AIMNet2 段不要和别人的 `vasp_std` 抢卡；可与本项目 gpu4pyscf 共卡 |
| **Parent 默认 CPU** | e0 里 Parent 精修默认 CPU；teacher 的 GPU 波才是 gpu4pyscf parent |
| **`--skip-train-live`** | 编排器 **只跑 e0、不启动训练**（避免误训） |

## 2. 和 mindmap 步骤的对应（别跳步）

```text
0–1  冻结分子根 + Train/Val/Test 划分
 2   teacher（老师帧）          ← CPU pilot + GPU autofill
 3   Epoch-0 基线               ← g001 Epoch-0 · g002 Epoch-0 · g003 Epoch-0 …
 4–5 只在 Train 上训练 + 多 checkpoint
 6–7 quick-val 筛选（非终选）
 8–9 完整 sci-val 终选
10   冻结身份
11–12 Final Test 一次 · 禁止事后淘货
```

**当前工程主线卡在：步骤 2 收尾 + 步骤 3 进行中。**  
训练（4–5）要等 teacher/e0 策略与授权；**Final Test 默认密封**。
